# 旧 ADR 处置清单

- 日期: 2026-07-19
- 对象: `docs/archive/ARCHITECTURE_DECISIONS.md` 中的 ADR-001 ~ ADR-017
- 背景: 产品定位已由 `PRODUCT_VISION_v2.md` 重新定义(从"文献库工具"转向"研究项目 copilot"),原 17 条 ADR 需逐条重审。归档文件本身保持原样不动,本文档是其处置结论的唯一权威来源。

## 保留(决策依然成立,可直接沿用)

ADR-005(PDF 四层 fallback)已经在 `packages/tools/src/fulltext/` 中落地实现,回退顺序 LaTeX → HTML → PDF 文本 → OCR 与决策一致,继续有效。ADR-009(PDF 处理逻辑归属 packages/tools)同样已按此落地。ADR-010(统一 Result 错误模式)是与定位无关的工程规范,沿用。ADR-011(SubAgent Prompt 版本控制)在精读 SubAgent 成为核心能力后反而更重要,沿用。ADR-013(SubAgent 质量测试方法)同理沿用。ADR-014(fork 后复制宿主测试套件防回归)在确定 fork OpenCode 后直接适用,fork 完成后第一时间执行。

## 修订(方向成立,细节需按新架构重写)

ADR-002(OpenAI 兼容 API):目标不变,但实现路径变了——OpenCode 经由 AI SDK 天然支持多 provider,不再需要自建兼容层,该决策降级为配置约定。ADR-003(SubAgent Token 池隔离):隔离原则保留,但依据从"OpenCode 已实现"改为"由我们自己的编排层保证";且新定位下精读是小批量深度处理,原先担心的大规模并行 token 爆炸场景弱化。ADR-004(批量成本确认):机制保留,触发场景从"导入 200 篇"收窄为少数批量操作。ADR-006(RESEARCH.md 串行写入):串行化写入原则保留,但写入对象从单一 markdown 文件变为记忆图谱及其投影,具体方案随记忆底座设计重定。ADR-007(Active Papers 加载策略):演化为记忆图谱的按需上下文加载策略,原有的分层思想(索引层/活跃层)被吸收进新设计。ADR-012(数据一致性检查):原则保留,检查对象改为新的记忆结构。ADR-015(批量处理并发策略):保留并发控制思想,优先级下调。

## 废弃或推迟(与新定位冲突,或服务于被放弃的场景)

ADR-001(完整实现全部 Phase 的范围策略)被 PRODUCT_VISION_v2 的四阶段路线图取代,废弃。ADR-008(论文访问统计)服务于大文献库的冷热分层,新定位下项目内活跃论文数量少,推迟到确有需求时再议。ADR-016(完整 RAG 系统 + Papers Index 扩展)与 ADR-017(DuckDB + vss 选型)整体降级:向量检索不再是核心架构,仅作为底座中的粗筛手段,推迟到记忆底座稳定之后按需实现;届时选型结论(DuckDB + vss)可作为起点重新评估。

## 需要新增的决策

新架构引入了旧 ADR 未覆盖的决策点,新决策以独立文件存放于 `docs/adr/`。已落定:ADR-018(fork 基座选定 OpenCode 最新版,采纳 Effect 作为编排层实现基底)。待相应设计展开时补充:项目记忆图谱的存储形态与投影机制;精读笔记的 schema 与版本演化策略;稿件 claim 与引用、实验的关联表示。
